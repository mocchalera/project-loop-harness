# project-loop-harness v0.5.5

**Prepared:** 2026-07-29

**Status:** Published and publicly verified

**Scope:** finish reliability, explicit target binding, and operator-visible
execution

This release packages the completed post-v0.5.4 real-use friction remediation.
It makes finish checks safer to run, keeps explicit Task/Goal intent attached
through routing and execution, and makes long finish operations observable and
reviewable without requiring a full machine-state dump.

## Highlights

### Safer, reproducible finish execution

- `pcl finish --emit-packet` fingerprints verification inputs, runs configured
  checks in an independent temporary Git copy, and compares input/effect state
  before accepting completion proof.
- Check Evidence records structured runner/assertion results, failure phase,
  timeout/termination details, input manifests, and cold/warm stability.
- Compatible immutable check results may be reused by exact execution identity
  and role; tampered or policy-incompatible history fails closed.
- Bounded timeout recovery preserves the exact target and stops at a finite
  diagnostic route instead of silently retrying forever.

### Explicit target and lifecycle binding

- `pcl start --task` and `pcl start --goal` attach new intent to an explicit
  existing target without duplicating Goal/Task state.
- `pcl next --target` and finish/resume routes retain exact Task/Goal scope and
  fail closed on missing, ambiguous, or inconsistent targets.
- Shared terminal-readiness evaluation keeps Task listings, finish, lifecycle
  closure, and routing aligned.
- Scoped audit diagnostics separate current Task-owned anomalies from unrelated
  repository history.
- Execution binding and `progress-receipt/v1` preserve target, worktree,
  attempt, and checkpoint provenance across progress and resume surfaces.

### Observable and compact finish operations

- `pcl finish --progress jsonl` emits phase/check heartbeats and a terminal
  delivery receipt on stderr while preserving stdout JSON semantics.
- `--summary`, pagination, and `--exclude-machine-state` provide bounded actual
  result projections without weakening or truncating durable packet Evidence.
- A current healthy exact-goal completion packet now routes `pcl next` to an
  agent-safe, evidence-bound `pcl goal close` command instead of repeating the
  full finish suite.
- Repository-current packet reuse evaluates Git identity from the packet's
  validated recorded base, including an explicit ancestor base, instead of
  falsely treating every non-HEAD-base packet as stale.
- Stale, superseded, wrong-target, incomplete, high-risk, or non-latest packets
  never route to closure; timeout recovery retains precedence.

## Compatibility and boundaries

- Existing command defaults, completion-packet/v1, public JSON fields, exit
  semantics, and direct/workflow Goal authority remain backward compatible.
- New flags, receipts, and result fields are additive.
- DB schema remains **8**; no migration is added.
- Runtime dependencies remain empty and Python support remains 3.10-3.13.
- The isolated finish workspace is a repository-safety boundary, not an OS,
  network, or filesystem sandbox.
- Core remains local-only. No telemetry, hosted state, automatic Cockpit/GitHub
  mutation, provider execution, or publication action is added.
- Broader P1 proposals such as completion-packet/v2, automatic Cockpit ingest,
  history projection, flake quarantine, migrations, and dependencies are not
  included.
