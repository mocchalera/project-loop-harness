# Proof workspace v1

P1-C C2 adds an internal, effect-zero `proof_workspace` service. It creates a
fresh, exact Git candidate workspace and binds explicitly declared non-Git
inputs. It does not execute proof checks or authorize reuse.

## Boundary

C2 implements three strict additive contracts:

- `verification-profile/v1` is the only check-plan source;
- `proof-workspace-spec/v1` binds the candidate, C1 resolution, frozen
  bootstrap profile, verification profile, isolation contract, and typed
  external-input declarations;
- `proof-workspace-binding/v1` records deterministic public repository,
  authority, profile, input, check, and proof-key bindings.

All three reject additional fields. `terminal_authority` and
`mandatory_evidence` are literal `false`. `reuse_authorized` is always
`false`.

C2 adds no `pcl proof` CLI, process result, proof artifact, Evidence, event,
outbox row, database write, render, lifecycle transition, or terminal input.
SQLite remains schema 8; migration, dependency, and PCL semantic effects are
all zero.

## Authority and identity

The service independently canonicalizes and hashes the full
`authority-surface-resolution/v1`, `bootstrap-authority-profile/v0`, and
`verification-profile/v1` objects and matches them to the spec. Target,
candidate commit, and candidate tree must agree exactly.

C2 copies the C1 `effective.reuse_allowed`, `risk_level`, and
`human_gate_required` fields. It never infers permission from risk alone. Any
`reuse_allowed is not True` changes the separate runtime disposition from
`eligible` to `fresh_only` and adds `proof_authority_reuse_forbidden`. No
operation moves that disposition back to eligible.

Diff validation follows `base.status`:

- `resolved`: recompute the canonical base-to-candidate diff in the sealed
  isolated clone and require exact entries and digest equality;
- `base_unknown`: do not invent a base or run a diff; remain fresh-only;
- `no_candidate_change`: require base equals candidate and the canonical empty
  diff; remain fresh-only.

The direct `actual_diff_sha256` proof-key field is deliberately redundant with
the authority-resolution digest. It exists for local diagnostics and is never
an independent authority source.

## Git isolation

The canonical root may be a primary or linked worktree. C2 resolves its exact
top-level, Git common directory, object directory, and object format. Candidate
reachability is checked against the same object store and local path that is
then cloned. The exact commit must be reachable through source `HEAD`, a head,
or a tag. Ref movement that prevents the exact object from transferring fails
closed; C2 does not create refs, copy objects, use alternates, fetch a network
remote, or substitute `HEAD`.

Every C2 Git subprocess, including C1 `canonical_git_diff` and its `_git_bytes`
path and the unchanged verification-manifest collector, uses one `GitRunner`
instance with a complete environment constructed from zero. Inherited
`GIT_DIR`, `GIT_OBJECT_DIRECTORY`, `GIT_INDEX_FILE`, configuration injection,
replace objects, loader injection, prompts, and parent HOME/TMP state are not
present.

The service runs local `git clone --no-local --no-checkout`, removes all remotes
before checkout, sets `core.hooksPath` to an absolute owned empty directory,
and checks out the exact commit detached. Clone and source common/object
directories must differ. Alternates, promisor/partial-clone configuration,
unsafe config, remotes, LFS smudge, and external filters are rejected or
disabled. No `.gitmodules` or `.lfsconfig` URL is followed.

The committed tree is independently checked by mode, object type, full OID,
regular-file bytes, executable bit, symlink target bytes, and gitlink identity.
The same representation, except declared typed replacements, is resealed before
spawn and after a future check.

## Typed external inputs

External source locators are in-memory path capabilities and are not public
binding fields. Supported declarations are:

- a regular, non-symlink, single-link file with exact bytes, size, and portable
  mode;
- a deterministic directory bundle containing normalized directories, regular
  files, and safe relative symlinks;
- a submodule binding the superproject gitlink and an explicitly supplied local
  repository's exact commit, tree, and object format; mixed superproject and
  submodule object formats remain fresh-only without an exact mapping proof;
- materialized Git LFS bytes matching the committed pointer, or generated bytes
  matching an exact absent/placeholder base expectation;
- an opaque dependency, which is never materialized and is always fresh-only.

Missing/unreadable material follows its declaration's `fresh_only` or `block`
policy. Integrity mismatches never degrade to fresh-only. Nested `.git` or
`.project-loop` in directory bundles, protected destinations, overlaps,
case-fold collisions, hardlinks, FIFOs, sockets, devices, unsafe file kinds,
absolute or escaping symlinks, and digest disagreement fail closed.

Files use `O_NOFOLLOW` and `O_CLOEXEC`, descriptor reads, pre/open/post/final
identity checks, exclusive destination creation, and copied bytes as authority.
Directory bundles use descriptor-relative traversal, copied entry bytes, and
complete source manifests before and after materialization. Materialized input
digests are resealed before a future spawn.

## Prepared checks and environment privacy

`PreparedCheck` is frozen and is the only permitted future spawn vector. It
contains the final argv (including resolved executable), absolute owned cwd,
complete environment, timeout, output cap, plan/tool/environment bindings, and
`spawn_vector_sha256`.

The complete environment starts empty. It receives only profile-allowlisted
names from the explicitly supplied parent snapshot plus owned HOME/TMP and fixed
Git controls. `PYTHONPATH` is absent unless built from workspace-relative
entries; canonical host `root/src` is forbidden. `PYTHONHOME`, `BASH_ENV`,
loader variables, inherited `GIT_*`, shell startup variables, HOME/TMP, and
similar runtime-control inputs cannot be inherited.

The public binding records allowlisted names and a digest of logicalized
non-secret name/value pairs, but never values. Owned workspace, HOME, TMP,
hooks, config, input roots, and resolved tools use stable logical tokens.
Secret-shaped allowlisted values remain only in the in-memory complete
environment, force fresh-only, and make the public spawn digest `null`;
secret-derived digests are never serialized.

`verification-input-manifest/v1` is unchanged and is used only for effect
classification within one workspace. Its root-dependent digest is not part of
candidate or shared proof identity.

## Lease and lifecycle

C2 is POSIX Linux/macOS only. Each invocation creates an independent OS temp
root and an exclusive `0600` lease marker. Ownership binds the canonical temp
parent, exact child, root device/inode, marker device/inode/link count, and a
random nonce.

Successful context completion performs descriptor-relative deletion of the
exact verified root. Failure and process crash retain the root. Marker/root
replacement refuses cleanup and retains the path. Later calls never sweep or
adopt retained roots, and repeated cleanup of a successfully cleaned in-memory
lease is a no-op.

Operational state and reuse disposition are distinct. Preparation progresses
through authority-bound, owned, cloned, sealed, detached, initially-clean,
inputs-materialized, checks-prepared, and ready states. Contract/integrity
failure is blocked and retained; pre-spawn drift becomes invalid and lowers the
runtime disposition to fresh-only. C2 never enters running, passed, reused,
anchored, approved, or terminal states.

This is repository/input isolation, not an OS or network sandbox. A hostile
same-user process that mutates and restores state wholly between observations,
undeclared absolute paths/services, dynamic library closure, and network state
remain outside the claim. Native Windows and automatic cleanup of crash roots
are intentionally deferred.

## C3 and C4 handoff

C3 must independently rederive the complete C1 resolution, base-status diff,
shared proof key, public execution binding, tool identity, complete environment
checksum, and `spawn_vector_sha256` immediately before spawn. It must consume
the existing `PreparedCheck` directly with `shell=False`. It must not call
`build_subprocess_env`, merge `os.environ`, prepend canonical host `src`,
re-resolve PATH, or reconstruct argv/cwd/env. C3 owns bounded execution,
results, immutable artifacts, future events/outbox projection, and any reusable
anchor; none exists in C2.

C4 owns mandated canary and role-coverage enforcement at the parallel join.
Structural validity of a C2 verification profile does not claim that its roles
cover the frozen canary contract. C4 must reject an incomplete role/canary set;
C2 deliberately does not infer that semantic approval.
